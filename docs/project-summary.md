# 项目摘要 · newone（毕业要求检查系统）

> 这份文档的定位是**一页看懂现状**。工程细节在 `README.md`（369 行，8 节），
> 业务口径在 `docs/domain-logic-and-tools.md`（482 行，技术栈无关），
> 在线化设计在 `docs/superpowers/specs/`，分支进度在 `docs/branch-summary-online-v2.md`。
> 本文不重复它们，只回答「现在到底是什么状态」。

## 1. 这个系统在做什么

给定「学生身份」（学年 + 主修 + 可选辅修/EXTM + 分支选择）与「一组课程状态」（每门课：未选 / 已修 / 计划），
输出「每个要求组还差多少学分」。

三条不可动摇的前提（决定所有技术决策的边界）：

1. **权威数据是官方培养方案 PDF**，系统持有的是它的结构化抄本 —— 所以每条抽取都留 PDF 页码出处，且允许人工修订。
2. **LLM / 解析器只允许出现在离线阶段**。上线运行的系统读的是已固化、已校对的成品，运行时不做任何推断。
3. **不确定就降级**。无法判定的规则一律保留官方原文并标记存疑，绝不猜 —— 猜错会算错学分，比不算更糟。

## 2. 五段数据流（现状：全部跑在离线，产出静态文件）

```
官方 PDF ──① 解析(MinerU)──② 抽取(LLM)──③ 分支标记──④ 与课程库交叉核对
                                                          ↓
                                     pipeline/output/**  （255 份 JSON，人工可编辑的权威源）
                                                          ↓
                                     ⑤ 烘焙 export_static_data.py + courses.db
                                                          ↓
                                     frontend/public/data/**  （4 份静态文件 + 255 份方案树）
                                                          ↓
                                     学生浏览器 SPA  ← 核算引擎在前端纯函数里跑
```

关键点：**分母与缺口全部在浏览器里算**，服务器只负责发静态文件。没有账号，没有后端，
勾选状态存 localStorage。

| A | **线上旧系统** | 正常运行，**未被本次任何改动触碰** | `origin/main` = `67effce`，Cloudflare Pages 部署静态站 |
| B | **分支上的结构改造** | 10 个提交，**未 push** | `feat/online-v2`：领域层移进 `packages/domain`、根 npm workspaces、四道数据闸门、源格式规范化 |
| C | **分支上的新后台（试用）** | 能跑、能浏览 255 份方案，但**与 A/B 都没有数据连线** | `apps/studio`（Payload 3.90.2 + Next 16 + MongoDB 适配器）+ 试用容器 `newone-payload-trial` |
| D | **两份设计文档** | v1 已部分作废，v2 是当前依据 | `docs/superpowers/specs/2026-09-15-arch-refactor-design.md`（v1）、工作区 `online-graduation-check-design-v2.md`（v2） |

**所以对你的问题的完整回答**：是「旧服务照样 + 增加新后台」，但要点是
① 新后台目前是个**孤岛**，它改了数据不会流到任何用户面前；
② 旧服务的**行为**没变，但**代码布局**变了（领域引擎换了位置，靠别名重定向，79 个消费方一行未改）；
③ 权威源文件的**格式**被统一过一次（255 份全改），但实测重烘焙后成品只有 `meta.json` 一行时间戳变化 —— 即语义零变化。

## 5. 决策史（为什么现在长这样）

| 时间 | 决策 | 内容 |
|---|---|---|
| 2026-09-15 | **v1 spec** | 前后端完全分离：Nuxt3 + NestJS + MongoDB Atlas + Vercel 容器，全量重写、不保留旧站 |
| 2026-09-26 | **选型** | 现成整站 degree audit 被证据否决（它们只渲染学校算好的 audit，不自行核算）→ 回落整套栈；用户选 **Payload**，且要求 **DB 为编辑权威** |
| 同上 | **口径冲突裁决** | 「DB 为编辑权威」与领域文档 §1/§5「产物为源、手改成品被 CI 拦」相撞 → 解法是**双写回环**：git 仍是可复现账本，DB 只是编辑入口 |
| 同上 | **范围** | 不做学生登录 / 个资 / 云端存档（勾选继续留 localStorage）；语言不锁死；旧站保留、新分支并行对拍，更优才并主干 |
| 同上 | **撤回 v1 三条** | D1 全量重写、D6 管线改 TS、D9 用 Nuxt —— 分别改为并行对拍、管线保持 Python、学生端沿用现有 React SPA |
| 2026-09-27 | **T2b** | 成绩单 PDF 的浏览器 IO 适配器（含 Vite 专有 `?url`）拆出领域层，否则后端一 import 就炸 |
| 2026-09-27 | **ADR-12** | 「谁是格式权威」定案：255 份源统一为 `indent=2 + ensure_ascii=False + 整数值不写 22.0`，实测该形式是不动点 |

## 6. 已知的坑与坏数据（不要当测试基准）

- **5 份产物待重跑**：2026-27 `MATH`（Track 组名全丢、总学分算成 174）、2024-25 `MATH`（产物几乎为空）、2026-27 `ACCT`、2026-27 `GCS`、2025-26 `ELEC`。共同病症是抽取阶段丢 Track/Option 组名 —— **这是抽取契约的缺陷，新栈重做抽取时必须写成硬性要求**。
- **通识核心新增 Area 后总数是 33 学分，与官方「30 学分」表述不一致** —— 属已知待校准项，不是 bug。
- **`min_courses` 有消费端无生产端**：实测 **0/1753** 组有值。
- **通识课程映射表**（75,633 字节）的原始输入 PDF 与生成脚本都已不在仓库，更新只能重解析官方 PDF 后手工维护。
- **原始 PDF 不在仓库**（约 156 MB，gitignore）：clone 后跑不了管线，但已提交产物足以跑起整站。
- **重跑抽取要花钱**（上万页量级、数十美元档），所以「无损搬运、不在下游重算」是硬约束。

## 7. 还没做的事（按依赖顺序）

2. **ADR-10** 归一化规则目前有两份实现（Python 烘焙器 / TS `source-pdf.ts`）—— T9 前必须收敛
3. **T9** 双写回环 —— 做完才谈得上「后台改数据能上线」
4. **F3 的裁决**：后台改一棵 1,718 行的 JSON 树，体验与今天用 VS Code 改文件**无实质差别**。
   为 Payload 付出的代价是已量的：`node_modules` 790 MB、双 React（19 与 18 共存）、上游 1,948 个版本 / 2026 年已发 344 次。
   **收益尚未证明** —— 这是当前最大的开放问题。
5. 其余收口：ADR-8 双 lockfile、ADR-9 `packages/domain` 不在 eslint 覆盖内、ADR-11 匿名读一刀切、ADR-13 seed 写放大版本表。

## 8. 一分钟自检（任何人在任何机器上都能跑）

```bash
npm run verify        # 六道门：数据基线 · 平移忠诚度 · 源格式 · 数据断言 · 112 单测 · 构建
npm run probe:audit   # 在 Node 里跑领域引擎，看 §4.1/§4.2/§4.4 三条口径的真实数字
```

`verify` 里的「平移忠诚度」门会拿 `67effce`（引擎搬家之前）逐字比对现在的 21 个领域文件，
这是「换栈没换口径」这句话的可证伪版本。
